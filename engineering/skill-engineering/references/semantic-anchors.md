# Semantic Anchors

Catalog: https://llm-coding.github.io/Semantic-Anchors/

Semantic anchors are shared names for established methods, frameworks, or principles. They compress stable meaning. They do not replace a concrete scope, output format, or validation.

## Selection

1. Search the catalog when a named standard could remove repeated explanation.
2. Verify the anchor's canonical meaning from its primary source when output depends on it.
3. Use one anchor only when the user, artifact, and task match it.
4. State the anchor beside its job: `C4 — diagram scope`, not merely `Use C4`.
5. If no standard fits, use short explicit criteria. Never invent an anchor.

## Common fits

| Need | Anchor | Use |
|---|---|---|
| Software architecture diagrams | C4 | System, container, component, code views |
| Architecture documentation | arc42 | Structured architecture communication |
| Requirement completeness | EARS, Given-When-Then | Testable requirements and acceptance criteria |
| Security control review | OWASP ASVS, CWE | Applicable controls and weakness classification |
| Operational reliability | SLO, error budget | User-facing reliability decisions |
| Concise decision communication | BLUF | Outcome before supporting detail |
